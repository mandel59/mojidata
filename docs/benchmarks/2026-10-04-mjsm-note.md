# MJ shrink-map note quota evidence

Measured locally on 2026-10-04 before implementation, comparing the existing
SQL with the proposed correlated `mjsm_note` primary-key lookup.

Source: `packages/mojidata/dist/moji.db`, SHA-256
`c8cd43031d6a48bde6b131f0fd0fb778301627846c4b65ff038937884c21ea6b`.
The source contains 58,862 MJI rows and 1,776 reference-note rows.

For D1-style shrink-map lookup, a temporary materialized `mjsm` table was
created from the source view with the three indexes used by the importer:

```sql
CREATE TEMP TABLE mjsm AS SELECT * FROM main.mjsm; CREATE INDEX temp.mjsm_MJ文字図形名 ON mjsm(MJ文字図形名); CREATE INDEX temp.mjsm_縮退UCS ON mjsm(縮退UCS); CREATE INDEX temp.mjsm_表 ON mjsm(表);
```

Only `mjsm` was materialized; the other source views remain intact. These are
local SQLite scaling measurements, not Cloudflare billed read counts. Full
response measurements include the complete generated SQL; `unihan_rs` keeps
its existing separate queries and therefore contributes no changed work.

Every proposed query uses:

```text
SEARCH mjsm_note USING INDEX sqlite_autoindex_mjsm_note_1 (MJ文字図形名=?)
```

The added lookup returns at most one row per MJ glyph. A local UNION of
`(対応するUCS, MJ文字図形名)` and `(実装したUCS, MJ文字図形名)`, grouped by
UCS, found a maximum of 16 glyphs (邉). Thus the added work is at most 16
unique indexed point lookups per request for this artifact. This is a dataset
bound, not a permanent Unicode invariant; recheck it after data updates.
No new API SQL statements, recursion, reverse edges, searches, import writes
or request fan-out are introduced. `select` excluding `mji` adds zero lookups.
Broad/no-hit property searches, variant graph traversal and Latin-1 fallback
retain their existing SQL. The IVS case above characterizes the DB layer;
the public endpoint retains its existing single-character validation.

The current importer already exports `mjsm_note` and its primary-key index.
Reuse the existing DB for a code-only release; no reimport or migration is
needed. Tests cover notes with no shrink target, absent notes, per-glyph
association, full responses, selection exclusion, and the indexed plan.

This change is implemented and verified locally only. Remote validation,
rollout, retries and rollback have a zero allocation in this review. Account
usage was not queried; the complete daily allowance is conservatively reserved
for existing use and normal traffic across all databases. Before any future
deployment, verify the target artifact/indexes and fresh aggregate account
usage, budget the complete workload and retain the old code for rollback.
Stop if an index is absent, cost/usage is unknown, or the budget cannot fit.
Do not use remote scans, benchmarks or imports to resolve those unknowns.
